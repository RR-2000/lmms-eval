# MOVi-A motion diagnostics

This task evaluates the five-choice records generated by
`build_movi_a_motion_dataset.py`. It uses the ordered 24 RGB frames as the
baseline input and expands an identical, deterministically selected set of
source QIDs into paired ground-truth scaffold conditions.

The default data locations are now:

- QA and GT: `/home/ramanathan/data/movi_a_motion`
- RGB and segmentation frames: `/home/ramanathan/data/movi_a_train_export`

Set `RAMANATHAN_DATA_ROOT` to move both together, or override them separately
with `MOVI_A_MOTION_ROOT` and `MOVI_A_TRAIN_EXPORT_ROOT`. The loader rebases
stale paths embedded in `frames_json` onto the configured frame root whenever
the rebased file exists. Set
`MOVI_MOTION_SAMPLES_PER_SUBTASK` to control the deterministic number of source
questions selected per subtask (default: 100; `-1` means all records).

## Detailed trace mode

Set `MOVI_MOTION_TRACE_DIR` to save a complete post-hoc analysis bundle in
addition to the normal metrics. Each expanded scaffold condition gets one JSON
record under `records/` containing the source document, scaffold configuration,
exact task prompt, model-rendered chat prompt, processor tensor shapes, response,
parsed answer, and score. The exact ordered visual inputs are saved as
content-addressed PNGs under `media/`; repeated frames are stored once. A
contact-sheet preview for each distinct visual sequence is stored under
`previews/`.

Use this together with `--log_samples`, which produces the standard lmms-eval
per-task JSONL files. For example:

```bash
MOVI_MOTION_SAMPLES_PER_SUBTASK=20 \
MOVI_MOTION_TRACE_DIR=outputs/movi_trace/trace_bundle \
python -m lmms_eval \
  --model qwen3_vl_experiments \
  --model_args max_num_frames=32,pretrained=Qwen/Qwen3-VL-8B-Instruct \
  --tasks kubric_movi_a_motion_oracle_ladder \
  --batch_size 1 \
  --log_samples \
  --output_path outputs/movi_trace
```

The repository-level `pbs_movi_a_motion_detailed_sample.sh` runs all diagnostic
suites as a four-element PBS array on 160 deterministic source question-clips
(20 from each of eight subtasks). In the current dataset these cover 158
distinct simulation sequences and expand into 8,180 scaffolded evaluations.
It enables `MOVI_MOTION_DERIVED_NUM_FRAMES=12`, which selects 12 label-aware
frames while preserving original frame IDs and recalculates targets, options,
comparison winners, prompts, overlays, and every diagnostic scaffold from the
displayed evidence. Setting this variable to `0` retains the original 24-frame
task unchanged.

Set `MOVI_MOTION_NUMERIC_SCALE_GUIDE=1` to add a shared, perspective-correct
on-screen ruler to every numerical-answer condition, including the baseline.
The ruler is labelled in scene units for a camera-plane segment at the target
object's depth, so its pixel length changes correctly as the target moves
toward or away from the camera. The `state_only_no_visual` condition receives
a scale-only panel with no scene pixels. Categorical answer tasks are unchanged.
The repository-level `pbs_movi_a_motion_12f_full_scale_guide.sh` runs the full
100-per-subtask, 12-frame experiment library as four parallel PBS array elements.

Available tasks:

- `kubric_movi_a_motion`: unassisted baseline.
- `kubric_movi_a_motion_visual_scale_assistance`: paired numerical-task ablation
  containing an unassisted baseline, the legacy lower-left ruler, and an
  object-anchored ruler. The anchored form boxes the target in cyan, connects
  the ruler to it, aligns the ruler with the longer projected target side, and
  chooses the lower-occlusion of the two outside placements. It is usable
  without setting `MOVI_MOTION_NUMERIC_SCALE_GUIDE`.
- `kubric_movi_a_motion_oracle_ladder`: video-only through answer-letter oracle.
- `kubric_movi_a_motion_perception_diagnostics`: boxes, masks, visibility, and tracks.
- `kubric_movi_a_motion_temporal_diagnostics`: labels, endpoints, query triplets, intervals, events, and timing.
- `kubric_movi_a_motion_coordinate_diagnostics`: world/camera state, basis, distance trace, trajectory plot, and direction conventions.
- `kubric_movi_a_motion_calculation_diagnostics`: formulas and intermediate arithmetic quantities.
- `kubric_movi_a_motion_representation_diagnostics`: table, JSON, and graphical state representations.
- `kubric_movi_a_motion_precision_diagnostics`: two-, four-, and eight-decimal GT state.
- `kubric_movi_a_motion_robustness_controls`: coordinate noise, reversed frames, irrelevant state, and explicitly mismatched state.
- `kubric_movi_a_motion_diagnostics`: group containing every diagnostic task.

The GT sidecar is loaded lazily from `ground_truth/<sequence_id>.json`; the
large frame-level Parquet table is not loaded into memory. Every result keeps
both `qid` and `source_qid`, enabling paired gains and baseline-error rescue
counts. Quantities retain the generator's `scene units` labels.

Example:

```bash
MOVI_MOTION_SAMPLES_PER_SUBTASK=50 python -m lmms_eval \
  --model internvl3_5 \
  --model_args pretrained=OpenGVLab/InternVL3_5-8B \
  --tasks kubric_movi_a_motion_oracle_ladder \
  --batch_size 1
```
